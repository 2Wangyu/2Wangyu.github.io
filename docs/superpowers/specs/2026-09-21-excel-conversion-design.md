# 本地 Excel 转换工具设计

## 目标

在现有工具中心新增「Excel 处理」分类，并首先提供 PDF 表格、图片表格和 Word 表格转 Excel 三个浏览器本地工具。访问者选择文件后，文件、识别结果和下载过程都只在当前浏览器中处理，不传送到服务器，也不写入本地持久存储。

## 信息结构

工具中心左侧导航升级为分类列表。既有文本、开发、时间和安全工具保持可访问；新增「Excel 处理」分类，其下包含：

1. PDF 表格转 Excel
2. 图片表格转 Excel
3. Word 表格转 Excel

PDF 处理、图片处理、Word 处理作为未来分类入口保留在信息架构中，但第一期不显示不可用的按钮，避免把未完成的功能伪装为可用工具。

## 统一转换流程

每个转换工具使用同一工作区框架：

1. 展示格式说明、隐私提示和选择文件区域。
2. 在浏览器内读取文件，显示处理状态与可取消/重新选择入口。
3. 将识别到的数据统一成二维字符串数组，并呈现在可编辑表格中。
4. 用户可修改单元格内容、添加或删除行列，并选择工作表名称。
5. 使用客户端 Excel 导出库生成并下载 `.xlsx` 文件。

## 三个工具的边界

### PDF 表格转 Excel

使用 PDF 解析器读取文字型 PDF 的页面文本、坐标和页面尺寸，再按行列位置组合为表格预览。对于扫描 PDF，工具明确提示需要使用「图片表格转 Excel」流程；第一期不承诺自动区分所有复杂合并单元格或多张表格。

### 图片表格转 Excel

使用 WebAssembly OCR 在浏览器内识别 PNG、JPG、JPEG、WebP 的文字。第一期按文本行和横向空白推断表格列，随后交给用户在预览中修改。清晰、正面拍摄且边框或列间距明确的图片是推荐输入；模糊、倾斜、手写或复杂合并单元格必须提示用户校对。

### Word 表格转 Excel

只接受 `.docx`，读取文档内部表格并按每张 Word 表格创建一个 Excel 工作表。普通正文、图片、页眉页脚和排版样式不导出。旧版 `.doc` 会提示另存为 `.docx` 后再处理。

## 技术方案

工具页面继续采用原生 ES Modules。文件选择通过浏览器 File API 完成；PDF 使用 pdf.js，图片文字识别使用 Tesseract.js WebAssembly worker，DOCX 读取使用 JSZip/XML 解析，Excel 下载使用 SheetJS。依赖文件随静态网站发布，不把用户文件发送给第三方服务；OCR 中文和英文语言包也应随网站提供，首次使用不产生外部数据请求。

转换器模块都输出 `{ sheets, warnings }`：`sheets` 为 `{ name, rows }` 数组，`rows` 为二维字符串数组；`warnings` 为应显示给用户的可读提示。共享的编辑器与导出模块只处理这个稳定结构，从而让未来的新格式转换器复用同一套界面。

## 错误处理与隐私

- 不支持的扩展名、空文件、无法解析的文件或受密码保护的 PDF 需要给出明确中文提示。
- 单次文件上限设为 20 MB；超过上限不读取内容。
- 处理期间只显示文件名、文件大小和本地进度；不记录文件内容。
- 页面刷新、切换工具或重新选择文件时清除内存中的文件与识别结果。
- Excel 导出失败时保留编辑表格，并提示重新下载。

## 验收与测试

- 注册表可按「Excel 处理」筛选并链接到三个工具。
- 三种转换器分别验证扩展名、空文件、正常二维表格输出及不可解析文件的错误结果。
- 共享工作表编辑器验证单元格、行、列修改后能生成正确的二维数组。
- Excel 导出器验证多个工作表的名称与行数据会交给导出库。
- 工具页面结构测试覆盖文件选择、隐私说明、预览表格和下载按钮。
- 浏览器人工检查三种工作流在桌面与手机宽度均无横向页面溢出。
